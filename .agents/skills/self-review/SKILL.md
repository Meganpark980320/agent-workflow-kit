# 스스로 반박하기

사람이 리뷰하며 할 질문을 먼저 스스로 던지고 답을 기록한다. 사람은 결과만 확인하면 되게 한다.

1. `OWNER_CHECKLIST.md`(이미 읽었으면 다시 열지 않는다)를 이번 결과에 적용한다. 해당 없으면 건너뛴다.
2. **반례 찾기:** "이 결론이 틀렸다면 무엇이 보여야 하나?"를 한 줄로 쓰고, 그걸 실제로 찾아본다(데이터·로그·테스트).
3. **다른 길로 재계산:** 핵심 숫자 1~3개를 다른 방법(다른 도구·직접 세기·표본 원문)으로 다시 낸다. 다르면 원인을 찾을 때까지 결론을 미룬다.
4. **민감도:** 임계값·기간·필터를 바꾸면 결론이 뒤집히는지 한 번 본다.
5. **출력 분포·표본 확인 (분류·판정·탐지 결과일 때):** 라벨이 없는 전체 결과의 분포를 표로 본다(클래스·경고별 개수). 한쪽으로 쏠렸거나 예상과 다르면, 각 클래스에서 2~3개씩 원본을 직접 열어 맞는지 본다. 적은 검증 표본의 정확도만 믿지 않는다.
6. **경계 입력:** 빈 값·이상한 값·큰 값으로 기능이 무너지지 않는지 테스트를 하나 이상 추가한다.
7. 결과를 `docs/VERIFY.md`(검증)와 `docs/DECISIONS.md`(판단이 바뀌었으면)에 남긴다. 스스로 틀린 걸 잡았으면 REPORT의 'AI를 어떻게 썼나'에 사례로 적는다.
8. 사람에게는 한 줄로: "반박 점검: <무엇을 확인했고 결론이 유지/수정됐는지>".
