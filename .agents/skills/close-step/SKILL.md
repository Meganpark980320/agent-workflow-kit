# 단계 닫기

1. 검증을 실제로 실행한다(테스트·샘플 입력·손계산 대조·`curl`·화면 동작). 명령과 출력 요지를 남긴다.
2. 결론이 걸린 단계면 self-review를 짧게 돈다(반례·재계산 중 최소 하나).
3. `docs/VERIFY.md`에 해당 R번호 줄을 채운다: 확인 방법 / 기대 / 실제 / 판정(통과·실패·미검증).
4. 이번 단계에서 고른 것이 있으면 `docs/DECISIONS.md`에 한 줄: 결정 / 다른 선택지 / 근거.
5. 실패면 원인을 한 줄 적고 계획을 고친다. 같은 시도를 반복하지 않는다.
6. 통과면 `git add -A` 다음 `git commit -m "R번호: 무엇을 왜"`를 **각각 따로** 실행한다(다른 명령과 묶지 않는다). 승인 요청이 뜨면 사용자에게 승인을 부탁한다. `docs/PLAN.md`의 상태를 '완료'로.
7. 사용자에게 한 줄로 진행 상황(무엇이 됐고 어떻게 확인했는지)을 남기고 **다음 단계로 바로 넘어간다.** 멈추는 것은 AGENTS.md의 세 경우뿐이다.
